# Broom

面向 Windows 桌面的安全、可撤销垃圾清理工具。Broom 只处理由规则明确声明的缓存目录：先扫描预览，再把文件移入隔离区，清理后随时可以撤销。

当前版本 **v4**：在 v3 的 **管理员系统级缓存清理** 之上，完成 **隔离区管理与两阶段空间释放**。清理后的文件先暂存在隔离区，首页可查看暂存体积与磁盘剩余空间；在隔离区中可以按文件或按会话恢复，只有确认永久释放后才会真正回收磁盘空间。v2 的回收站清空与只读分析、v3 的系统级缓存清理继续保留。

当前开发版同时完成 **v1.1 安全与可管理性**：新增**设置页**（主题、语言、规则开关、排除列表与保留策略入口）、**中英文界面**，以及预览页的**逐文件选择**。此外还加入了**排除列表**、**隔离区完整性校验**、**未完成清理会话提示**、**清理断点续跑**、**文件占用检测**与**跳过 / 失败分类**：排除项优先于所有规则，并在扫描、清理与撤销三个环节统一校验；隔离条目会记录文件大小与小文件的 SHA-256，恢复前重新校验；清理开始前会持久化完整选中清单，中断或崩溃后可在隔离区继续未完成的清理；预览阶段会提示可能被占用的文件，清理结果把跳过与失败分开统计。

规则与类别也已扩展：**Review 级缓存规则进入普通扫描但默认不勾选**，需要手动选择并额外确认；新增缩略图 / 图标、DirectX / GPU、日志诊断、常见应用、Cargo / Go / NuGet / Maven / JetBrains 等开发缓存、浏览器扩展脚本缓存，以及管理员工具中的 Windows.old 清理。当前内置 **31 条用户规则 + 3 条管理员规则**，兼容边界见 [docs/roadmap.md](docs/roadmap.md)。其他平台与清理能力尚未实现。

## 如何定义“垃圾”

Broom 不使用启发式猜测，也不按扩展名全局搜索。垃圾文件必须同时满足一条声明式规则和一组运行时约束：

1. **规则声明位置**：每个规则用环境变量与通配符声明一组缓存根目录，例如 Chrome 的 `Cache`、`Code Cache`、`GPUCache`，以及 npm / pip / Pub / Gradle 缓存。
2. **必须位于规则根目录内**：扫描到的文件只能属于该规则的某个根目录；删除与撤销时还会再次校验，防止规则写错或路径拼接越界。
3. **可选时间与扩展名过滤**：例如用户临时文件只处理超过 24 小时的内容，崩溃转储只处理 `.dmp`。
4. **跳过符号链接 / junction**：扫描不会跟随链接，避免通过链接跳出缓存目录。
5. **不触碰受保护区域**：Windows 目录、Program Files、Program Files (x86)、ProgramData 以及 Broom 隔离区始终受保护；规则根本身不会被删除。

当前内置规则按类别与风险级别分组：

| 分类 | 规则 | 级别 | 主要位置 / 额外限制 |
| --- | --- | --- | --- |
| 系统缓存 | 用户临时文件、崩溃转储、Windows 错误报告 | Safe | `%TEMP%`（>24h）、`CrashDumps`（仅 `.dmp`）、WER `ReportArchive` / `ReportQueue` |
| 缩略图与图标缓存 | 资源管理器缩略图与图标缓存 | Safe | `%LOCALAPPDATA%\Microsoft\Windows\Explorer` 下的 `.db`；Explorer 占用的文件会跳过 |
| DirectX / GPU 缓存 | DirectX 与显卡着色器缓存 | Safe | `D3DSCache`、NVIDIA / AMD / Intel 的明确缓存目录 |
| 日志与诊断 | 应用日志与诊断 | Safe | VS Code、Teams、Slack、Discord 的 `logs`；仅 >7 天，不含 Windows 事件日志 |
| 浏览器缓存 | Chrome、Edge、Brave、Firefox | Safe | profile 下的网页、代码、GPU、Service Worker 缓存；不碰书签、密码、历史 |
| 浏览器扩展缓存 | Chromium 扩展脚本缓存 | Safe | 单 profile 的 `ScriptCache`；不碰扩展程序、状态与设置 |
| 应用缓存 | Teams、Slack、Discord、Spotify、VS Code | Safe | 明确的 Cache / Code Cache / GPUCache / Service Worker 等目录 |
| 开发工具缓存 | npm、pip、Pub、Gradle、Yarn、pnpm、Bun、Composer | Safe | 仅包下载 / 构建缓存；不碰项目与全局工具 |
| 开发工具缓存 | Docker Desktop 日志、WSL 崩溃转储 | Safe | 仅 Windows 侧日志与崩溃转储；不直接删除 WSL 虚拟磁盘、镜像或容器 |
| 开发工具缓存 | Cargo、Go、NuGet、Maven、JetBrains | Review | 体积大、需要重新下载或重建索引；默认不勾选 |
| Windows 升级残留（管理员） | Windows.old | Review | 仅系统盘根目录 `Windows.old`；永久删除，无撤销，可能包含旧用户配置文件副本 |
| Windows Update / 传递优化（管理员） | 更新缓存、传递优化缓存 | Review | 固定系统路径；清理期间临时停止相关服务，永久删除 |

- 普通扫描包含全部已启用的 Safe 与 Review 规则。Safe 规则默认勾选；Review 规则默认不勾选，勾选后需要额外确认。两类规则都通过 Broom 隔离区清理，可撤销。
- 管理员工具完全独立：使用原生 API 解析固定路径，默认不勾选，永久删除，不进入隔离区。Windows.old 只在确认系统稳定且已备份所需文件后使用。
- 浏览器、应用和开发工具规则都只覆盖明确声明的缓存子目录，不包含账号、登录状态、项目源码、用户设置或文档。

## 安全模型

- **声明式规则**：只清理规则覆盖的路径，不做全盘“垃圾识别”。
- **规则审计**：每条内置规则（含系统缓存规则）都带有风险等级、双语评审说明、反向证据以及正反回归样例。`test/rule_audit_test.dart` 强制审计字段完整、每个路径模板同时覆盖命中与拒绝样例，并用真实的 `WindowsRuleResolver` 与 `JunkScanner` 在临时文件树上验证实际扫描结果；新增规则缺少任一项或样例行为不符时测试会失败。预览中的规则详情页可打开“规则审计”查看这些说明。
- **路径守卫**：Windows 大小写不敏感地检查路径包含关系，拒绝根目录本身、`..` 越界与同前缀的兄弟目录。
- **排除优先**：用户维护的排除列表优先于所有 Safe 与 Review 规则；被排除目录及其子目录不会扫描，清理与撤销也会再次校验。
- **不跟随链接**：目录遍历使用 `followLinks: false`，遇到 `Link` 直接跳过。
- **移动而非删除**：清理先把文件移动到隔离区；运行中的程序占用的文件会自动跳过并保留在原处。报告把占用、文件消失、符号链接与排除项归为“跳过”，把权限、路径校验与 IO 错误归为“失败”，两者分开展示，不强制解锁。
- **占用检测**：扫描完成进入预览后，通过原生 `broom/file_lock` 通道以 `CreateFileW(..., DELETE)` 只读探测每个候选文件；共享冲突（`ERROR_SHARING_VIOLATION` / `ERROR_LOCK_VIOLATION`）标记为“可能被占用”。预览页显示每项规则的占用数量与逐项图标，被占用文件仍可勾选。探测不写入、不解锁，失败或不支持时静默降级，清理开始前自动取消。详见 [docs/file-lock-detection.md](docs/file-lock-detection.md)。
- **跨卷兼容**：同卷优先 `rename`，跨卷退回“复制 + 删除”，删除失败时清理复制出的半成品。
- **长路径与 UNC**：接近或超过 `MAX_PATH` 时自动使用 `\\?\` / `\\?\UNC\` 扩展长度路径；程序清单声明 `longPathAware`，原生元数据通道同样支持。会话记录与界面始终保存不带前缀的规范路径，路径守卫对 UNC 共享和大小写不敏感比较。验证范围与操作步骤见 [docs/filesystem-validation.md](docs/filesystem-validation.md)。
- **崩溃安全**：移动每个文件前，先把撤销记录追加写入并 `flush`；即使清理中途崩溃，已移动的文件仍可撤销。
- **空目录清理**：清理或续跑完成后，仅删除规则根内因本次文件移出而变空的目录；规则根本身、清理前就已存在的空目录，以及仍含未选中或跳过文件的目录都会保留。删除每个目录前写入重建记录，撤销时按路径守卫与排除列表校验后重新创建。
- **完整性校验**：隔离记录保存每个文件的大小；不超过 32 MiB 的文件额外记录 SHA-256。恢复前重新检查大小与哈希，异常文件禁止恢复并继续留在隔离区。
- **可撤销**：撤销前重新做路径守卫检查；遇到原位置已有文件时可选跳过、保留两者（恢复为“名称 (已恢复).扩展名”）或覆盖（需二次确认，并在替换前再次校验）。支持按文件或按会话恢复。
- **两阶段空间释放**：清理只把文件移入隔离区，不会立刻腾出磁盘空间；只有确认为永久释放后，隔离区文件才会被删除并回收空间。
- **可选自动保留**：默认不自动删除隔离区内容；用户可开启保留天数与容量上限，Broom 在启动时永久释放最旧的超限会话，启用前必须确认该操作不可恢复。
- **默认不提权**：普通 Safe / Review 扫描与清理以当前用户权限运行；只有独立的系统级缓存与 Windows.old 工具会通过 UAC 重新启动管理员窗口。
- **Review 规则默认不勾选**：普通扫描会显示 Review 结果，但不会预选；勾选后必须再确认。Review 文件仍进入隔离区并可撤销，但可能包含需要重新下载的离线数据或需要重建的索引。
- **系统级缓存单独处理**：Windows Update、传递优化与 Windows.old 不属于普通规则，使用原生 API 解析的固定目录、逐文件根目录校验与永久删除确认；不会混入普通缓存列表，也没有撤销入口。

## 使用流程

1. 可选：打开右上角“设置”，调整主题、界面语言，或关闭某些 Safe / Review 规则；也可以在“本次扫描范围”中打开“排除列表”，把不希望 Broom 触碰的目录排除。
2. 点击“开始扫描”。扫描会处理全部已启用的 Safe 与 Review 规则，在独立 isolate 中执行，可随时取消；单次扫描最多收集 100,000 个文件，达到上限会提示截断。
3. 在预览页按规则查看文件数量、体积与风险级别。Safe 规则默认勾选，Review 规则默认不勾选；可以按规则勾选，也可以在规则详情中逐文件勾选，并支持全选、反选与跨规则汇总。扫描后会在后台探测“可能被占用”的文件并显示图标与数量，但仍可勾选。
4. 确认后仅将选中的文件移入隔离区；如果选了 Review 规则，对话框会再次说明后果并要求勾选确认。被占用、已消失或已排除的文件会归入“跳过”，无权限、路径校验或 IO 错误归入“失败”；两类结果分开列出，其余文件继续处理。
5. 清理完成后可“撤销本次清理”，或进入“隔离区”查看所有待处理会话。隔离区支持按文件 / 按会话恢复、恢复全部、按会话或整体永久释放；冲突文件可选择跳过、保留两者或覆盖；永久释放前必须勾选不可恢复确认。如果清理中止或崩溃，隔离区会保留未处理清单，可点击“继续清理”从断点接着处理；启动时也会弹窗提示未完成会话。

## V1.1：设置、双语与逐文件选择

- **设置页**：首页右上角齿轮进入。可切换跟随系统 / 浅色 / 深色主题与跟随系统 / 简体中文 / English 界面语言；按规则单独开启或关闭扫描，Review 规则会显示风险徽标；提供排除列表、隔离区保留策略入口，以及隔离区路径的复制与定位。设置保存在 `%LOCALAPPDATA%\Broom\settings.json`（schemaVersion 1），保存失败会回滚并提示，读取失败时回退到默认设置。
- **规则开关**：关闭的规则不会进入扫描任务；首页扫描范围中的规则会标记“已关闭”。排除列表仍然优先于所有规则。Review 规则即使启用，也只会在预览中显示并保持未勾选。
- **国际化**：界面文案集中到 `lib/l10n/`，通过 `LocalizationsDelegate` 提供简体中文与 English，并接入 `flutter_localizations`；日期与数字使用 `intl` 按当前语言格式化。规则标题、描述与系统缓存服务名称均提供英文版本。核心层与 Windows 原生调用返回的错误详情可能仍为中文。
- **逐文件选择**：预览页的规则卡片显示三态复选框与已选数量；进入“查看”后可按文件勾选、全选、取消全选与反选。底部操作栏汇总跨规则已选文件数与预计暂存体积，清理时只提交选中的文件。

## 清理断点续跑

- **清理前写计划**：开始移动文件前，把本次选中的完整清单写入会话目录的 `plan.jsonl`；每个文件移动前仍先追加撤销记录，因此已移动的文件不会因中断而失去撤销能力。
- **中断识别**：用户停止清理或清理过程中出错时，会话状态为 `partial`，并记录未处理数量。若应用硬崩溃，遗留的 `cleaning` 会话会在下次启动时按计划与撤销记录重新计算未处理数量。
- **继续清理**：未完成会话在隔离区列表和详情页显示“待继续清理”与剩余数量，可点击“继续清理”。继续过程只处理没有撤销记录的条目，已移动的文件不会被再次处理，也不会碰触中断后在原位置新出现的文件；过程中可再次停止。
- **完成与放弃**：全部条目处理完后会删除 `plan.jsonl`，会话转为正常的待恢复状态。恢复全部隔离文件或永久释放会话会一并放弃剩余计划。
- **边界**：断点续跑覆盖“已经开始清理”的阶段。扫描结果尚未持久化，扫描阶段中断后仍需重新扫描，见路线图第 3 节。

## 元数据恢复

- **清理时记录**：每个条目保存创建 / 修改 / 访问时间与只读属性；跨卷移动还会抓取文件的 DACL。ACL 只保存 DACL，不保存所有者、组与 SACL。
- **恢复时应用**：文件内容回到原位置（或冲突时的新名称）后，通过原生 `broom/file_metadata` 通道一次性应用时间戳、DACL 与只读属性。只读属性最后设置，避免影响时间戳与 ACL 的写入。
- **同卷与跨卷**：同卷重命名本身保留 ACL 与属性；只有跨卷复制会创建带目标目录继承 ACL 的新文件，因此也只在这种情况下额外抓取并恢复 DACL。恢复时会带上原来的继承 / 保护状态。
- **失败处理**：元数据恢复失败不会撤销已经恢复的文件内容，也不会让会话停留在待处理状态；失败数量作为独立警告显示在恢复结果中。旧会话没有这些字段时，只恢复修改时间。
- **只读文件**：跨卷移动与永久释放前会临时清除只读位，否则 Windows 无法删除源文件；删除失败时会尝试恢复只读位。
- **边界**：FAT/exFAT、权限不足或 ACL 抓取失败时保留目标 ACL；隐藏 / 系统属性与备用数据流不做独立恢复，仍依赖文件系统的移动 / 复制语义。

## V4：隔离区管理与空间释放

清理和释放磁盘空间是两个阶段，v4 把这套语义完整呈现给用户：

- **暂存不等于释放**：隔离区通常与缓存位于同一磁盘，清理只是把文件移动到 `%LOCALAPPDATA%\Broom\quarantine`，磁盘可用空间不会立即增加。首页、清理预览与完成页统一使用“暂存”措辞，并提示永久释放后才会腾出空间。
- **磁盘可用空间**：通过原生 `GetDiskFreeSpaceExW` 查询隔离区所在磁盘的可用 / 总空间，显示在隔离区摘要卡中；查询失败时不影响隔离区其他操作。
- **会话与条目管理**：隔离区页列出全部待处理会话及暂存体积；进入会话可逐项查看原路径、体积与状态（可恢复 / 原位置已有文件 / 完整性异常 / 隔离文件缺失 / 已恢复）。
- **完整性校验**：每个条目记录文件大小，不超过 32 MiB 的文件额外记录 SHA-256。会话页用大小快速标记异常条目并禁止勾选恢复；实际恢复前会再次校验大小与哈希，不一致的文件保留在隔离区，可永久释放。
- **未完成会话提示**：清理崩溃遗留的 `cleaning` 会话会被归一为 `partial`。Broom 启动后会弹窗提示未正常结束的会话，可直接进入隔离区继续恢复或永久释放；首页待处理卡片也会标明未完成次数。
- **按范围恢复**：支持勾选单个文件恢复、全选可恢复项、恢复全部。恢复遇到原位置已有文件时可选择跳过、保留两者（重命名副本）或覆盖；覆盖需要二次确认，并在替换前重新校验路径守卫。恢复成功的条目记录在 `restored.jsonl`，失败或跳过的条目保留在隔离区。
- **永久释放**：按会话或整体永久删除隔离区文件，是不可撤销操作。确认对话框要求勾选“我明白这些文件将被永久删除，且无法恢复”，并明确说明这一步才会真正回收磁盘空间；部分释放失败会逐项报告，失败文件继续保留。
- **保留与容量策略**：默认关闭。可在隔离区页开启“自动永久释放”，设置保留天数（默认 30 天）与占用上限（默认 5 GiB）。Broom 启动时先永久释放超过保留期限的会话，再按从旧到新的顺序释放，直到占用不超过上限；启用开关旁需勾选不可恢复确认。策略保存在独立的 `quarantine_policy.json` 中，配置损坏时自动停用而不会触发删除。

## 排除列表

首页“本次扫描范围”右侧提供“排除列表”入口，通过 Windows 原生文件夹选择器添加不希望 Broom 触碰的目录：

- **存储**：`%LOCALAPPDATA%\Broom\exclusions.json`，保存 `schemaVersion` 与绝对路径列表，与隔离区分离。
- **优先级**：排除优先于规则。规则根位于排除项之下时整个规则跳过；排除项位于规则根之下时只跳过该子树。首页会把受影响规则标记为“已排除”或“部分排除”。
- **二次校验**：扫描器跳过排除子树；清理与撤销逐项校验排除列表。配置读取失败时扫描会被阻止，页面提供重置，避免在不知道排除项的情况下删除文件。
- **限制**：只能添加已存在的文件夹，不能排除磁盘或共享根目录；与已有排除项重叠时需要先移除已有项。

## V3：系统级缓存（管理员模式）

首页“系统级缓存”工具用于清理 Windows Update、传递优化与 Windows.old。它与普通规则完全分离，属于 `REVIEW · 需确认`：

- **单独提权**：未提权时只显示权限说明，不提供扫描入口。点击“以管理员身份重新启动”后通过 `ShellExecuteExW`（`runas`）启动新的管理员实例，并携带 `--system-cache` 参数；新窗口只打开本页，不自动扫描或删除任何内容。
- **规范路径**：缓存根目录由 Windows 原生 API 返回——`GetWindowsDirectoryW` 得到 `%WINDIR%\SoftwareDistribution\Download`，`SHGetKnownFolderPath(FOLDERID_ProgramData)` 得到 `%ProgramData%\Microsoft\Windows\DeliveryOptimization\Cache`，系统盘 `Windows.old` 由 Windows 目录所在卷推导后校验目录名。不使用环境变量，不接受任意路径输入。
- **逐文件校验**：每个待删除文件必须位于该规则解析出的根目录内；拒绝根目录本身、越界路径、符号链接与 junction，只删除普通文件。Windows.old 可能因 TrustedInstaller 权限或文件占用而只能部分删除，失败项会保留并报告。
- **临时停止服务**：Windows Update 缓存对应 `wuauserv` 与 `bits`，传递优化缓存对应 `dosvc`。停止失败会中止清理；无论完成、失败还是取消，都会在 `finally` 中尝试重新启动已停止的服务，恢复失败会写入报告。Windows.old 不需要停止服务。
- **永久删除**：系统缓存与 Windows.old 体积大，移到同卷隔离区不会释放磁盘空间，因此不进入隔离区、没有撤销。扫描结果默认全部不勾选，必须手动选择规则，并在独立对话框中勾选“我明白系统缓存将被永久删除，且无法撤销”。
- **Windows.old 专项警告**：Windows.old 保留上一版 Windows，可能包含旧用户配置文件副本、旧程序和系统设置。选择后会显示独立警告，明确失去回滚能力且删除无法恢复；应先备份所需文件。当前系统、当前个人文件、更新历史与系统还原点不受影响。
- **占用提示与结果分类**：扫描后会复用文件占用探测，在规则卡片与操作栏提示可能被占用的文件；清理时共享冲突、文件消失与符号链接归入“跳过”，权限、服务与路径错误仍为“失败”，完成页分开展示。
- **边界**：只处理上述三个固定目录，不删除 Windows 更新历史、当前系统、系统设置或系统还原点，也不强制删除被占用的文件或解锁占用进程。Docker / WSL 的内部虚拟磁盘不在系统工具范围内。

## V2：分析与审阅（Review / Info）

首页“分析与审阅”区域提供四类工具，并明确标注风险等级：

| 等级 | 含义 | 当前入口 | 数据影响 |
| --- | --- | --- | --- |
| `SAFE · 可撤销` | 明确声明的安全缓存，可随时恢复 | 开始扫描 → Safe 规则 | 默认勾选，移入 Broom 隔离区 |
| `REVIEW · 需确认` | 可能导致离线数据重新下载、重建索引或失去回滚能力 | 开始扫描 → Review 规则；回收站；系统级缓存；Windows.old | 普通 Review 规则默认不勾选、额外确认，仍进入隔离区；系统工具与回收站为永久删除 |
| `INFO · 只读` | 只分析、不修改任何文件 | 重复文件、大文件分析 | 无 |

### 回收站（Review）

- 通过 Windows Shell API（`SHQueryRecycleBinW`）读取所有磁盘回收站的条目数与占用。
- 清空调用 `SHEmptyRecycleBinW`（不显示系统确认框、进度框与音效），覆盖所有磁盘。
- 清空前必须通过独立对话框并勾选“我明白清空后无法恢复”；Broom 不提供回收站撤销。
- 不读取回收站内的文件内容。

### 重复文件（Info）

- 先按文件大小分组，再比对首尾部分指纹，最后对候选文件做完整 SHA-256；避免对所有文件全量读取。
- 默认只分析不小于 1 MB 的文件，阈值可选 100 KB / 1 MB / 10 MB / 100 MB。
- 单次最多检查 200,000 个文件，按可释放空间降序展示重复组。
- 结果只读：不自动选择保留项、不提供删除按钮，只支持“在资源管理器中显示”。

### 大文件分析（Info）

- 扫描用户选定的文件夹，列出超过阈值的文件（默认 100 MB，可选 50 MB 至 5 GB）。
- 匹配结果按体积降序展示，最多列出 200 个；汇总仍统计全部匹配项。
- 只读取文件大小与位置，不删除、不移动、不修改文件。

两类分析都在独立 isolate 中执行，支持进度展示与取消；Broom 的隔离区目录始终排除在分析范围之外。默认分析目录为当前用户的 `Downloads`。

## Windows 原生桥接

回收站、文件夹选择器、“在资源管理器中显示”与磁盘可用空间查询通过 `MethodChannel('broom/shell')` 调用原生 Shell API；管理员权限、UAC 自重启与系统缓存目录通过 `MethodChannel('broom/system')` 提供；文件时间戳、只读属性与 DACL 的恢复通过 `MethodChannel('broom/file_metadata')` 提供。通道实现位于 `windows/runner/system_shell_channel.*`、`windows/runner/system_access_channel.*` 与 `windows/runner/file_metadata_channel.*`，不需要额外插件依赖。C++ 侧返回 `HRESULT` / Win32 错误码，Dart 侧会转换为可读的“Windows 错误 0x……”提示；UAC 被用户取消时会映射为“未提权”，不作为错误。

## 隔离区

默认位置：`%LOCALAPPDATA%\Broom\quarantine\<sessionId>\`

```text
<sessionId>/
  session.json     # 会话元数据：状态、条目数、总大小、待恢复数、计划数与未处理数
  plan.jsonl       # 本次清理的完整选中清单；全部处理完后删除
  entries.jsonl    # 原始路径、规则根、大小、SHA-256、时间戳、只读属性、可选 DACL 与隔离文件名
  removed_dirs.jsonl # 清理后删除的空目录路径与所属规则根，供撤销时重建
  restored.jsonl   # 已恢复文件的标记，重试时跳过
  files/           # 实际保存的文件（使用扁平化存储名）
```

会话全部恢复或永久释放后目录会被删除；仍有冲突、失败、未释放文件或未处理的清理条目时状态标记为 `partial`，重启后可继续处理。只要 `plan.jsonl` 存在且仍有未处理条目，隔离区就会提供“继续清理”。恢复前会重新校验隔离文件的大小与（若有）SHA-256；异常条目标记为“完整性异常”并禁止恢复，但可以永久释放。恢复时遇到原位置已有内容可选择跳过、保留两者或覆盖；撤销还会重建 `removed_dirs.jsonl` 中记录、且仍与本次会话条目相关的空目录，重建失败只作为警告报告。永久释放只删除 `files/` 下的普通文件，失败项会保留并报告。

隔离区管理页默认按创建时间倒序展示会话，摘要卡同时显示暂存体积、待恢复文件数与磁盘可用空间。自动保留策略默认关闭；开启后，Broom 在启动时以及保存策略后执行自动释放：过期会话优先，占用仍超过上限时从最旧会话开始继续释放，自动释放等同永久删除且不进入回收站。策略文件为 `%LOCALAPPDATA%\Broom\quarantine_policy.json`（schemaVersion 1）；文件缺失时使用“关闭 / 30 天 / 5 GiB”默认值，读取或校验失败时保持关闭并显示错误，绝不因配置损坏而删除文件。

## 开发

要求 Flutter 3.x（开发环境为 Flutter 3.47.7 / Dart 3.13.5）与 Windows 桌面构建工具链。

```bash
flutter pub get
flutter run -d windows
flutter analyze
flutter test
flutter build windows --release
```

构建产物位于 `build/windows/x64/runner/Release/`。FAT/exFAT、网络盘与物理只读介质的可选验证命令见 [docs/filesystem-validation.md](docs/filesystem-validation.md)。

## 平台与移动端扩展

平台差异集中在 `CleanerPlatform` 接口中：`isSupported`、`quarantineRoot`、`rules`、`resolveRoots`。`createCleanerPlatform()` 当前只返回 Windows 实现，其他平台返回 `UnsupportedCleanerPlatform` 并显示不支持页面，因此移动端可以接入而不影响桌面逻辑。

需要注意，当前核心实现（路径守卫、隔离区、扫描器、分析遍历器）直接使用 Windows 路径语义与文件系统移动语义。接入 Android / iOS 时不能只新增一份规则：还需要为 `CleanerPlatform` 增加文件系统与路径语义抽象，并处理 SAF / MediaStore、应用沙箱、权限申请和平台专属的撤销机制。具体拆解见 [docs/roadmap.md](docs/roadmap.md)。

## 已知限制

- 仅支持 Windows。普通扫描同时包含 Safe 与 Review 规则；Review 默认不勾选并需要额外确认，但仍通过隔离区清理。回收站、系统级缓存与 Windows.old 是独立 Review 工具。
- 系统级工具覆盖 Windows Update 的 `SoftwareDistribution\Download`、传递优化的 `DeliveryOptimization\Cache` 与系统盘 `Windows.old`，均为永久删除、无撤销；更新缓存清理期间会临时停止相关服务，服务恢复失败需手动启动或重启系统。
- Windows.old 可能包含旧用户配置文件副本与旧程序；即使以管理员运行，部分文件仍可能因 TrustedInstaller 权限或占用而删除失败。扫描仍受 100,000 文件上限约束，因此可能只清理已找到的部分。
- Docker 规则只处理 Windows 侧日志，WSL 规则只处理 `%LOCALAPPDATA%\Temp\wsl-crashes` 中超过 7 天的崩溃转储；镜像、容器、构建缓存、Linux 发行版文件系统与 `ext4.vhdx` 均由各自工具管理，Broom 不会直接删除或压缩虚拟磁盘。
- 开发工具缓存按默认安装路径声明。自定义 GOPATH、WSL 内缓存、容器内部缓存或非默认包管理器路径不会被猜测或扫描。
- 缩略图 / 图标缓存通常被资源管理器占用；Broom 会跳过占用文件，不重启或强制解锁 Explorer。日志规则保留最近 7 天，且不处理受保护的 Windows 事件日志与 CBS 日志。
- 应用缓存规则只覆盖 Teams / Slack / Discord / Spotify / VS Code 的明确缓存目录；不同版本路径可能变化，未识别的新路径不会被扫描。浏览器扩展规则只清理 Chromium `ScriptCache`，不碰扩展程序、扩展状态、设置与本地存储。
- 提权流程依赖交互式 UAC；自动化测试覆盖通道解析、路径校验、服务状态机与页面流程，真实 UAC 授权需手动验证。
- 预览支持按规则或逐文件勾选，但仍不能按规则类别筛选扫描；扫描范围固定为全部已启用的 Safe 与 Review 规则。
- 回收站清空覆盖所有磁盘且永久生效，Broom 不提供隔离或撤销。
- 重复文件与大文件分析只读，不提供清理操作；重复文件默认只分析 ≥ 1 MB 的文件，最多检查 200,000 个文件，大文件列表最多显示 200 项。
- 分析范围一次只能选择一个文件夹，不能配置排除目录；默认目录为 `Downloads`。
- 自动保留策略只在 Broom 启动时和保存策略后执行，没有后台定时清理；策略默认关闭，且自动释放等同永久删除。策略配置损坏时会自动停用，文件继续保留。
- 完整性校验以文件大小为基础，仅对不超过 32 MiB 的文件记录 SHA-256；更大的隔离文件只能检测大小变化，无法发现等长的内容修改。计算哈希会让清理额外读取一次这些小文件。
- 元数据恢复覆盖创建 / 修改 / 访问时间与只读属性。ACL 仅对跨卷移动尽力恢复 DACL（含继承 / 保护状态），不恢复所有者、组与 SACL；FAT/exFAT、权限不足或抓取失败时会保留目标 ACL 并给出元数据警告。隐藏 / 系统属性与备用数据流仍依赖文件系统移动 / 复制语义。
- 长路径、UNC 与网络盘已通过实机往返验证；只读失败路径使用写保护目录代理验证。FAT/exFAT 与物理只读介质需要对应设备，测试已提供但本机未执行，详见 [docs/filesystem-validation.md](docs/filesystem-validation.md)。真实写保护介质返回的 `ERROR_WRITE_PROTECT` 已有错误提示映射测试。
- 排除列表只能选择现有文件夹，不能按文件或通配符配置；配置损坏时会阻止扫描，需要在排除列表页重置。
- 设置页不包含定时任务、隔离区位置迁移与清理历史；配置版本不匹配时会回退默认设置，不执行自动迁移。
- 中英文界面覆盖应用文案与规则元数据，但核心层和 Windows 原生调用返回的错误详情可能仍为中文。
- 单次规则扫描最多 100,000 个文件；结果在扫描结束后一次性展示。
- 断点续跑只覆盖清理阶段。扫描在内存中进行且结果未持久化，扫描中断后不能从断点继续，需要重新扫描；清理计划会保存选中文件的原始路径。

完整路线图见 [docs/roadmap.md](docs/roadmap.md)。
