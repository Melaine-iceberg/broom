# Broom 路线图

本文档记录 v4 之后尚未实现的目标、约束与非目标。v1 / v2 / v3 / v4 已实现的部分只在开头列出，作为后续工作的基线；第 3 节的扫描引擎升级已在当前开发版完成，详见 [scanning-engine.md](scanning-engine.md)。

优先级含义：

- **P0**：安全、可撤销性或数据正确性问题，应先于新功能。
- **P1**：直接提升 v1 可用性的能力。
- **P2**：平台扩展、自动化与长期演进。

状态标记：`[x]` 已实现，`[~]` 部分完成，`[ ]` 未实现。

## v1 已实现基线

- Windows 桌面端、Flutter Material 3 中文界面，系统深浅色跟随。
- 11 条 Safe 级规则：用户临时文件、崩溃转储、WER 报告、Chrome / Edge / Brave / Firefox 缓存、npm / pip / Pub / Gradle 缓存。
- 规则声明 + 环境变量展开 + 通配符目录解析；扫描时跳过链接、按扩展名与修改时间过滤、跨规则去重。
- `PathGuard`：Windows 大小写不敏感包含检查，保护 Windows、Program Files、Program Files (x86)、ProgramData 与隔离区。
- isolate 扫描、进度回报、取消、目录错误计数、100,000 文件截断。
- 预览按规则聚合，可查看文件明细，按规则勾选后清理。
- 隔离区移动而非删除，跨卷复制回退；移动前写撤销日志；清理后可撤销。
- 撤销冲突跳过且保留会话；部分撤销会话重启后仍可重试；全部恢复后自动删除会话。
- 单元 / 集成测试覆盖路径守卫、规则解析、扫描器、isolate 通信、隔离区清理与撤销、首页空扫描流程。

## v2 已实现（Review / Info）

- **风险徽标**：Safe / Review / Info 三档在首页工具卡与分析页明确展示。
- **回收站（Review）**：原生 Shell 通道读取所有磁盘回收站的条目数与占用；永久清空调用 `SHEmptyRecycleBinW`，需独立对话框与不可恢复勾选，不进入隔离区。
- **重复文件（Info）**：大小预筛 + 首尾部分指纹 + 完整 SHA-256；可配置最小体积（默认 1 MB），单次最多 200,000 个文件；结果只读、不自动选择，仅支持在资源管理器中定位。
- **大文件（Info）**：按用户选定目录扫描超过阈值的文件（默认 100 MB），体积降序，最多展示 200 个；只读。
- **分析基础设施**：共享只读遍历器（跳过链接、排除隔离区、错误计数、截断保护），独立 isolate 执行，进度回报与取消。
- **原生交互**：`MethodChannel('broom/shell')` 提供回收站、文件夹选择器与“在资源管理器中显示”；C++ 侧错误码转换为可读提示。
- **测试**：重复文件、大文件、分析 isolate、Shell 通道、回收站确认流程与分析页只读行为。

## v3 已实现（管理员系统缓存）

- **独立入口与提权**：首页新增“系统级缓存”工具；未提权时只展示权限说明，通过 `broom/system` 通道检测管理员权限并使用 `ShellExecuteExW`（`runas`）重启自身，携带 `--system-cache` 参数；新实例只打开系统缓存页，不自动扫描或删除。
- **原生规范路径**：Windows Update 缓存与传递优化缓存分别由 `GetWindowsDirectoryW` 和 `SHGetKnownFolderPath(FOLDERID_ProgramData)` 解析，不使用环境变量，不接受任意路径输入，并校验目录形状。
- **Review 级清理流程**：独立扫描、默认不勾选、独立确认与永久删除文案；被清理文件不进入隔离区，也不提供撤销。
- **服务协调**：清理前临时停止 `wuauserv` / `bits` / `dosvc`，停止失败即中止；完成、失败或取消后都在 `finally` 中恢复已停止的服务，恢复问题进入报告。
- **纵深校验**：逐文件检查可信根目录、根目录本身、越界路径、链接与普通文件类型；只删除规则声明的缓存目录内的文件。
- **测试**：服务状态机（停止、超时、回滚、恢复失败）、永久清理器、规范路径校验、管理员通道、控制器默认不勾选与页面提权 / 确认流程。

## v4 已实现（隔离区管理）

- **两阶段空间语义**：统一“暂存 / 永久释放”措辞，明确清理不会立即释放磁盘空间；首页、预览、完成页与隔离区页使用一致的说明。
- **隔离区管理页**：列出全部待处理会话、暂存体积、文件数与状态；进入会话可查看每个文件的原始路径、体积与恢复状态。
- **按范围恢复**：支持单文件勾选、全选、恢复选中与恢复全部；恢复不覆盖原路径后来新建的文件，部分恢复后正确重算剩余待处理条目，全部恢复后才删除会话。
- **永久释放**：按会话或整体永久删除隔离区文件，要求独立确认与不可恢复勾选；只删除 `files/` 下的普通文件，失败项保留并报告，全部成功后才移除会话目录。
- **磁盘可用空间**：`broom/shell` 通道新增 `GetDiskFreeSpaceExW` 查询，隔离区摘要展示磁盘可用 / 总空间；查询失败不影响其他操作。
- **入口与测试**：首页待处理卡片与完成页均可进入隔离区；覆盖选择性恢复、永久释放确认、空状态、首页导航与原生磁盘空间通道。

## 1. 安全与正确性（P0）

- [x] **排除列表**：允许用户添加不参与扫描的路径，持久化并在规则解析、扫描、清理、撤销四个环节统一校验。
      - 已实现：`%LOCALAPPDATA%\Broom\exclusions.json`（schemaVersion 2，带文档类型标记；v1 自动迁移）保存规范化绝对路径；通过原生文件夹选择器添加，排除优先于规则；首页标记规则的“已排除 / 部分排除”范围；清理与撤销逐项校验；配置损坏时阻止扫描并提供重置。仅支持已存在的文件夹，拒绝磁盘 / 共享根目录与重叠项。导入配置允许暂时不存在的绝对路径，以便在外接盘连接前恢复；重叠路径仍会被拒绝。
- [x] **未完成清理会话启动提示**：清理崩溃遗留的 `cleaning` 会话会归一为 `partial`；首页初始化后若发现未正常结束的会话会弹窗提示，可直接进入隔离区恢复或永久释放，首页待处理卡片也会标明未完成次数。
      - 已实现：`CleanController.unfinishedSessions` 汇总 `partial` 会话，`HomePage` 首次加载后弹窗；提示每次启动最多出现一次，`--system-cache` 提权实例不打扰用户。
- [x] **清理过程断点续跑**：清理开始前把完整选中清单写入会话的 `plan.jsonl`，条目移动前仍先写撤销记录；中断或崩溃后，隔离区页会识别未处理数量并提供“继续清理”，从最后一条撤销记录之后继续，不重复移动已处理文件。
      - 已实现：会话新增 `plannedCount` / `remainingCount` 元数据，`session.json` 改为临时文件原子替换；中断后状态为 `partial`，硬崩溃遗留的 `cleaning` 会话会按计划与撤销记录恢复剩余数量。继续清理可停止，再次中断后仍可继续；全部处理完会删除计划文件并将会话转为 `ready`。扫描本身仍不可断点续跑，见第 3 节“扫描结果持久化与复用”。
- [x] **撤销会话管理页**：隔离区管理页展示全部待处理会话与条目详情，支持按文件 / 按会话恢复，以及单会话或整体永久释放。
- [x] **撤销冲突处理**：原位置已存在时支持“保留两者 / 覆盖（需二次确认）/ 跳过”三种选择。
      - 已实现：隔离区恢复入口统一弹出冲突处理对话框；保留两者自动生成“名称 (已恢复).扩展名”并避让已有文件；覆盖前重新校验路径守卫与排除列表，并要求勾选确认；覆盖采用同目录临时备份，移动失败时回滚原文件。
- [x] **恢复元数据**：清理时记录创建 / 修改 / 访问时间与只读属性，恢复后通过原生通道重新应用；跨卷移动时额外抓取并尽力恢复 DACL。
      - 已实现：`entries.jsonl` 新增 `created` / `accessed` / `readOnly` / 可选 `acl` 字段，旧会话回退为仅恢复修改时间。恢复内容成功后应用元数据；元数据失败只计入独立警告，不改变“内容已恢复”与剩余条目状态。跨卷移动会抓取 DACL 及其继承 / 保护状态，恢复时通过 `SetNamedSecurityInfoW` 应用；同卷重命名本身保留 ACL。不恢复所有者、组与 SACL；FAT/exFAT、权限不足或 ACL 抓取失败会保留目标 ACL 并显示警告。只读文件在跨卷移动和永久释放前会临时清除只读位以便删除。
- [x] **隔离区完整性校验**：每个条目记录文件大小，不超过 32 MiB 的文件额外记录 SHA-256；会话页用大小快速标记异常条目，恢复前重新校验大小与哈希，异常文件禁止恢复并保留在隔离区，可永久释放。
      - 已实现：`entries.jsonl` 新增可选 `sha256` 字段，旧会话缺少哈希时回退到大小校验；`listEntries` 检测大小不一致并标记“完整性异常”，`undo` 重新校验大小与哈希，`UndoReport.integrityFailureCount` 单独统计，恢复结果对话框与隔离区页会区分展示。超出上限的文件只校验大小。
      - 后续调整：上限由 32 MiB 下调到 256 KiB，因为哈希在界面 isolate 上同步执行，32 MiB 的文件会造成数百毫秒的界面停顿；旧的 `entries.jsonl` 仍按各自记录的值校验，无需迁移。
- [x] **隔离区保留与容量策略**：设置保留天数 / 最大占用，自动清理最旧会话；必须明确自动清理等同永久删除，需要用户开关与提示。
      - 已实现：默认关闭；可设置 1–3650 天与不小于 1 MiB 的占用上限（界面提供常用档位）。启用时必须勾选不可恢复确认。Broom 启动时先永久释放超过保留期限的会话，再按从旧到新的顺序释放直至占用不超过上限；单会话超过上限时也会被释放。策略保存在 `%LOCALAPPDATA%\Broom\quarantine_policy.json`（schemaVersion 2，v1 自动迁移），配置损坏时保持关闭并显示错误；隔离区页显示策略状态、执行结果与失败数量，可随时关闭。仅在启动与保存策略时执行，没有后台定时清理。导入或恢复默认配置只写入策略、不执行自动释放；导入时强制保持关闭。
- [~] **长路径与特殊文件系统**：验证超过 260 字符路径、UNC 路径、FAT/exFAT、网络盘、只读介质上的扫描、移动与撤销行为。
      - 已实现：新增 `WindowsPath` 扩展长度路径辅助并在扫描、分析、隔离区移动 / 撤销、元数据通道中启用；程序清单声明 `longPathAware`；路径守卫支持 UNC 与 `\\?\` 规范路径；错误报告区分写保护、网络路径、磁盘空间与文件系统不支持。实机验证通过：超过 260 字符的本地 NTFS / ReFS 路径、UNC 共享（含跨 UNC / 本地卷移动）、临时映射的网络盘；只读失败路径用拒绝写入 ACL 的临时目录代理验证。FAT/exFAT 与物理只读介质的可选测试已提供，但本机无对应设备，需按 [filesystem-validation.md](filesystem-validation.md) 在介质可用时运行。
- [x] **活跃进程 / 文件锁检测**：在预览阶段提示可能被占用的文件，或至少把“跳过”与“失败”在报告中区分展示；不采用强制解锁。
      - 已实现：新增 `broom/file_lock` 原生通道，以 `CreateFileW(..., DELETE, FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE, OPEN_EXISTING)` 探测；`ERROR_SHARING_VIOLATION` / `ERROR_LOCK_VIOLATION` 记为“可能被占用”。扫描进入预览后按 512 个一批后台探测，不改变默认选择；预览页与规则详情显示占用数量与逐项图标，被占用文件仍可勾选。探测失败或当前系统不支持时静默降级，清理开始前取消探测。`CleanReport` / `SystemCleanReport` 新增 `skippedCount` 与 `skips`：占用、文件消失、符号链接与排除项归为“跳过”，路径守卫、权限、记录写入与 IO 错误归为“失败”；首页、系统缓存完成页与断点续跑提示分开展示。探测与分类细节见 [file-lock-detection.md](file-lock-detection.md)。
- [x] **空目录清理**：清理或续跑完成后删除规则根内因文件移出而变空的目录，撤销时重建。
      - 已实现：只处理仍然空且位于规则根内、并作为已移动文件祖先的目录；规则根本身、清理前已存在的空目录，以及仍含未选中、跳过或失败文件的目录都会保留。删除前把 `path` / `rootPath` 追加写入会话的 `removed_dirs.jsonl`，删除失败会回滚记录；清理被取消时不执行，留给续跑完成时处理。撤销时只重建仍与会话条目相关的记录，并再次校验路径守卫与排除列表；`UndoReport` 新增重建数量、失败数量与明细，完成页、撤销结果和隔离区提示会展示。目录重建失败不改变文件恢复状态。
- [x] **规则审计机制**：每条规则需有评审说明、风险等级、反向证据和回归测试样例，避免新增规则时扩大删除面。
      - 已实现：`CleanerRule` 与 `SystemCacheRule` 新增 `audit` 字段，包含中英双语评审说明、反向证据，以及带路径模板、命中预期与文件年龄的 `RuleAuditSample`。当前 47 条生产规则（44 条用户规则 + 3 条管理员规则）全部补齐；`test/rule_audit_test.dart` 强制规则编号唯一、审计字段完整、每个路径模板至少覆盖一个正例与一个反例，并用真实的 `WindowsRuleResolver` / `JunkScanner` 在临时文件树上验证样例的实际扫描结果。规则详情页新增“规则审计”对话框，展示风险等级、评审说明、反向证据与正反样例数量。

## 2. 清理能力与规则（P1）

### 2.1 风险分级

- [x] **开放 Review 级规则**：Review 缓存规则已进入普通扫描，但与 Safe 规则分级处理。
      - 已实现：控制器扫描全部已启用的 Safe / Review 规则；Safe 规则默认勾选，Review 规则默认不勾选。首页与设置显示风险徽标，预览页单独提示 Review 数量，提交前必须勾选确认。Review 文件仍通过隔离区清理并可撤销，与系统级工具、回收站等永久删除入口保持区分。新增 Cargo、Go、NuGet、Maven、JetBrains 五条 Review 开发缓存规则及审计样例。
- [x] **Info 级只读分析**：已提供独立的重复文件与大文件分析工具，结果只展示、不提供清理操作；扫描规则本身仍不产生 Info 条目。
- [ ] **分级策略可解释**：在 UI 中展示“为什么这是 Safe / Review”，以及清理后可能丢失什么（如离线数据、重新下载成本）。当前已通过徽标、工具说明与回收站警告覆盖主要后果，尚未逐条解释规则。

### 2.2 Windows 类别

- [x] **回收站**：通过 Shell API 读取与清空，撤销语义与文件移动不同（回收站本身可恢复，清空后不可）。已提供独立确认与不可撤销警告。
- [x] **Windows 缩略图 / 图标缓存**：已新增 Safe 规则，仅扫描 Explorer 目录下的 `.db` 缓存；Explorer 占用文件会跳过，不强制解锁或重启。
- [x] **DirectX / GPU 着色器缓存**：已新增 Safe 规则，覆盖 `D3DSCache` 与 NVIDIA / AMD / Intel 明确声明的缓存目录。
- [x] **传递优化缓存**：已作为管理员系统缓存工具实现，不进入普通规则。
- [x] **Windows Update 缓存**：已实现 `SoftwareDistribution\Download` 的管理员清理；临时停止/恢复 Windows Update 与 BITS，采用永久删除与独立确认。
- [x] **Windows.old**：已作为管理员 Review 规则实现，不提供“一键自动清理”。需显式提权、手动选择、独立确认；永久删除且无撤销。界面说明回滚能力丢失，并提示其中可能保留旧用户配置文件副本、旧程序与系统设置。当前系统、更新历史与还原点不在范围内。
- [x] **日志与诊断文件**：已新增应用日志规则，保留最近 7 天；受保护的 Windows 事件日志、CBS 日志不在范围内。Docker 日志与 WSL 崩溃转储分别有独立规则与 7 天保留期。
- [x] **应用缓存**：已新增 Teams、Slack、Discord、Spotify、VS Code 规则，仅覆盖明确的缓存子目录；进程占用由既有锁探测处理。
- [x] **开发缓存扩展**：已新增 Yarn、pnpm、Bun、Composer、Cargo registry、Go、NuGet、Maven、JetBrains 规则；Cargo / Go / NuGet / Maven / JetBrains 为 Review 级。Docker 仅处理 Windows 侧日志，WSL 仅处理崩溃转储；镜像、容器、发行版文件系统与虚拟磁盘不直接删除。

      - 已实现：`QuarantineService` 可注入可用空间查询，在创建会话和移动文件前只统计跨卷复制所需字节（同卷重命名不计），空间不足时抛出 `QuarantineSpaceException`；清理与续跑使用同一检查。运行中遇到 `ERROR_DISK_FULL` / `ERROR_HANDLE_DISK_FULL` 会停止后续复制并保留可续跑的计划；复制失败会删除不完整的隔离副本。`main.dart` 通过 `broom/shell` 的 `GetDiskFreeSpaceExW` 查询隔离区卷；查询失败时按未知处理，不阻止清理。

- [x] **会话格式版本化**：`schemaVersion` 已存在，需要迁移器与向后兼容测试；未知版本必须拒绝处理而不是猜测。

## 非目标

以下内容不在 Broom 的产品方向内，或需要重新论证后才考虑：

- 注册表清理、驱动更新、内存 / RAM 加速、系统“优化”评分。
- 杀毒、反恶意软件或安全扫描。
- 通过启发式猜测删除“看起来没用”的个人文件。
- 强制删除、绕过文件锁、绕过系统权限或使用 root / 漏洞访问其他应用私有数据。
- 清理系统还原点、Windows Update 历史等不可逆或影响系统回滚的操作。Windows.old 仅在管理员工具中由用户显式选择、独立确认后永久删除；不提供自动清理或一键全部清理。
- 删除浏览器密码、Cookie、历史等隐私数据；v1 浏览器规则严格限定缓存。
- 自动清理用户下载目录中的“疑似垃圾”；此类内容只能作为可审阅的分析结果。
- 云端文件内容扫描；Broom 保持离线，不上传用户文件名或路径。
