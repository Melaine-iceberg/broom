# Broom 路线图

本文档记录 v4 之后尚未实现的目标、约束与非目标。v1 / v2 / v3 / v4 已实现的部分只在开头列出，作为后续工作的基线。

优先级含义：

- **P0**：安全、可撤销性或数据正确性问题，应先于新功能。
- **P1**：直接提升 v1 可用性的能力。
- **P2**：平台扩展、自动化与长期演进。

## v1 已实现基线

- Windows 桌面端、Flutter Material 3 中文界面，系统深浅色跟随。
- 11 条 Safe 级规则：用户临时文件、崩溃转储、WER 报告、Chrome / Edge / Brave / Firefox 缓存、npm / pip / Pub / Gradle 缓存。
- 规则声明 + 环境变量展开 + 通配符目录解析；扫描时跳过链接、按扩展名与修改时间过滤、跨规则去重。
- `PathGuard`：Windows 大小写不敏感包含检查，保护 Windows、Program Files、Program Files (x86)、ProgramData 与隔离区。
- isolate 扫描、进度回报、取消、目录错误计数、100,000 文件截断。
- 预览按规则聚合，可查看文件明细，按规则勾选后清理。
- 隔离区移动而非删除，跨卷复制回退；移动前写撤销日志；清理后可撤销。
- 撤销冲突跳过且保留会话；部分撤销会话重启后仍可重试；全部恢复后自动删除会话。
- 单元 / 集成测试覆盖路径守卫、规则解析、扫描器、isolate 通信、隔离区清理与撤销、首页空扫描流程。

## v2 已实现（Review / Info）

- **风险徽标**：Safe / Review / Info 三档在首页工具卡与分析页明确展示。
- **回收站（Review）**：原生 Shell 通道读取所有磁盘回收站的条目数与占用；永久清空调用 `SHEmptyRecycleBinW`，需独立对话框与不可恢复勾选，不进入隔离区。
- **重复文件（Info）**：大小预筛 + 首尾部分指纹 + 完整 SHA-256；可配置最小体积（默认 1 MB），单次最多 200,000 个文件；结果只读、不自动选择，仅支持在资源管理器中定位。
- **大文件（Info）**：按用户选定目录扫描超过阈值的文件（默认 100 MB），体积降序，最多展示 200 个；只读。
- **分析基础设施**：共享只读遍历器（跳过链接、排除隔离区、错误计数、截断保护），独立 isolate 执行，进度回报与取消。
- **原生交互**：`MethodChannel('broom/shell')` 提供回收站、文件夹选择器与“在资源管理器中显示”；C++ 侧错误码转换为可读提示。
- **测试**：重复文件、大文件、分析 isolate、Shell 通道、回收站确认流程与分析页只读行为。

## v3 已实现（管理员系统缓存）

- **独立入口与提权**：首页新增“系统级缓存”工具；未提权时只展示权限说明，通过 `broom/system` 通道检测管理员权限并使用 `ShellExecuteExW`（`runas`）重启自身，携带 `--system-cache` 参数；新实例只打开系统缓存页，不自动扫描或删除。
- **原生规范路径**：Windows Update 缓存与传递优化缓存分别由 `GetWindowsDirectoryW` 和 `SHGetKnownFolderPath(FOLDERID_ProgramData)` 解析，不使用环境变量，不接受任意路径输入，并校验目录形状。
- **Review 级清理流程**：独立扫描、默认不勾选、独立确认与永久删除文案；被清理文件不进入隔离区，也不提供撤销。
- **服务协调**：清理前临时停止 `wuauserv` / `bits` / `dosvc`，停止失败即中止；完成、失败或取消后都在 `finally` 中恢复已停止的服务，恢复问题进入报告。
- **纵深校验**：逐文件检查可信根目录、根目录本身、越界路径、链接与普通文件类型；只删除规则声明的缓存目录内的文件。
- **测试**：服务状态机（停止、超时、回滚、恢复失败）、永久清理器、规范路径校验、管理员通道、控制器默认不勾选与页面提权 / 确认流程。

## v4 已实现（隔离区管理）

- **两阶段空间语义**：统一“暂存 / 永久释放”措辞，明确清理不会立即释放磁盘空间；首页、预览、完成页与隔离区页使用一致的说明。
- **隔离区管理页**：列出全部待处理会话、暂存体积、文件数与状态；进入会话可查看每个文件的原始路径、体积与恢复状态。
- **按范围恢复**：支持单文件勾选、全选、恢复选中与恢复全部；恢复不覆盖原路径后来新建的文件，部分恢复后正确重算剩余待处理条目，全部恢复后才删除会话。
- **永久释放**：按会话或整体永久删除隔离区文件，要求独立确认与不可恢复勾选；只删除 `files/` 下的普通文件，失败项保留并报告，全部成功后才移除会话目录。
- **磁盘可用空间**：`broom/shell` 通道新增 `GetDiskFreeSpaceExW` 查询，隔离区摘要展示磁盘可用 / 总空间；查询失败不影响其他操作。
- **入口与测试**：首页待处理卡片与完成页均可进入隔离区；覆盖选择性恢复、永久释放确认、空状态、首页导航与原生磁盘空间通道。

## 1. 安全与正确性（P0）

- [x] **排除列表**：允许用户添加不参与扫描的路径，持久化并在规则解析、扫描、清理、撤销四个环节统一校验。
      - 已实现：`%LOCALAPPDATA%\Broom\exclusions.json`（schemaVersion 1）保存规范化绝对路径；通过原生文件夹选择器添加，排除优先于规则；首页标记规则的“已排除 / 部分排除”范围；清理与撤销逐项校验；配置损坏时阻止扫描并提供重置。仅支持已存在的文件夹，拒绝磁盘 / 共享根目录与重叠项。
- [ ] **长时间运行的清理会话恢复**：当前仅恢复“隔离区会话”，扫描与清理本身不可断点续跑；清理中崩溃可从会话撤销，但 UI 需要在启动时明确提示未完成会话。
- [x] **撤销会话管理页**：隔离区管理页展示全部待处理会话与条目详情，支持按文件 / 按会话恢复，以及单会话或整体永久释放。
- [x] **撤销冲突处理**：原位置已存在时支持“保留两者 / 覆盖（需二次确认）/ 跳过”三种选择。
      - 已实现：隔离区恢复入口统一弹出冲突处理对话框；保留两者自动生成“名称 (已恢复).扩展名”并避让已有文件；覆盖前重新校验路径守卫与排除列表，并要求勾选确认；覆盖采用同目录临时备份，移动失败时回滚原文件。
- [ ] **恢复元数据**：当前只恢复文件内容。需评估恢复修改时间、只读属性、ACL；ACL 恢复涉及权限差异，优先级低于时间戳。
- [ ] **隔离区完整性校验**：为条目记录大小与可选哈希，恢复前校验，检测隔离文件被外部修改或截断。
- [x] **隔离区保留与容量策略**：设置保留天数 / 最大占用，自动清理最旧会话；必须明确自动清理等同永久删除，需要用户开关与提示。
      - 已实现：默认关闭；可设置 1–3650 天与不小于 1 MiB 的占用上限（界面提供常用档位）。启用时必须勾选不可恢复确认。Broom 启动时先永久释放超过保留期限的会话，再按从旧到新的顺序释放直至占用不超过上限；单会话超过上限时也会被释放。策略保存在 `%LOCALAPPDATA%\Broom\quarantine_policy.json`（schemaVersion 1），配置损坏时保持关闭并显示错误；隔离区页显示策略状态、执行结果与失败数量，可随时关闭。仅在启动与保存策略时执行，没有后台定时清理。
- [ ] **长路径与特殊文件系统**：验证超过 260 字符路径、UNC 路径、FAT/exFAT、网络盘、只读介质上的扫描、移动与撤销行为。
- [ ] **活跃进程 / 文件锁检测**：在预览阶段提示可能被占用的文件，或至少把“跳过”与“失败”在报告中区分展示；不采用强制解锁。
- [ ] **空目录清理**：当前只移动文件，可能留下空缓存目录。需决定是否在清理后安全删除规则根下的空目录，且撤销时可重建。
- [ ] **规则审计机制**：每条规则需有评审说明、风险等级、反向证据和回归测试样例，避免新增规则时扩大删除面。

## 2. 清理能力与规则（P1）

### 2.1 风险分级

- [ ] **开放 Review 级规则**：模型已含 `CleanRisk.review`，但规则清理控制器仍只接受 `safe`；v2 的回收站是独立 Review 工具。需要独立的预览、默认不勾选、醒目标识与更严格的撤销/保留策略后再启用 Review 缓存规则。
- [x] **Info 级只读分析**：已提供独立的重复文件与大文件分析工具，结果只展示、不提供清理操作；扫描规则本身仍不产生 Info 条目。
- [ ] **分级策略可解释**：在 UI 中展示“为什么这是 Safe / Review”，以及清理后可能丢失什么（如离线数据、重新下载成本）。当前已通过徽标、工具说明与回收站警告覆盖主要后果，尚未逐条解释规则。

### 2.2 Windows 类别

- [x] **回收站**：通过 Shell API 读取与清空，撤销语义与文件移动不同（回收站本身可恢复，清空后不可）。已提供独立确认与不可撤销警告。
- [ ] **Windows 缩略图 / 图标缓存**：`%LOCALAPPDATA%\Microsoft\Windows\Explorer` 下的缓存文件，处理时需考虑 Explorer 占用。
- [ ] **DirectX / GPU 着色器缓存**：`%LOCALAPPDATA%\D3DSCache`、NVIDIA / AMD / Intel 缓存目录。
- [x] **传递优化缓存**：已作为管理员系统缓存工具实现，不进入普通 Safe 规则。
- [x] **Windows Update 缓存**：已实现 `SoftwareDistribution\Download` 的管理员清理；临时停止/恢复 Windows Update 与 BITS，采用永久删除与独立确认。
- [ ] **Windows.old**：涉及系统回滚，默认不提供一键清理，需单独设计保留期、空间提示与恢复边界。
- [ ] **日志与诊断文件**：Windows 日志、应用崩溃日志、安装日志；必须逐类声明位置与保留策略。
- [ ] **应用缓存**：Teams、Slack、Discord、Spotify、VS Code 等常见应用的缓存目录；需要版本差异与活跃进程检测。
- [ ] **开发缓存扩展**：Yarn、pnpm、Bun、Cargo registry、Go module cache、NuGet、Maven、Composer、Docker、WSL、JetBrains、Android SDK / AVD。部分目录体积大且重新下载成本高，建议 Review 级并提示后果。
- [ ] **浏览器扩展缓存与旧版本目录**：先验证不会影响扩展状态与配置文件。
- [x] **系统级缓存（管理员模式）**：已提供独立提权流程、固定规则集、默认不勾选、逐文件校验与单独确认；不把提权作为“清理更多”的默认路径。

### 2.3 非缓存类清理

- [x] **大文件浏览**：按大小排序、按用户选定目录扫描；只读展示，不自动清理。
- [x] **重复文件检测**：大小预筛 + 部分哈希 + 完整哈希；不自动选择保留项，只展示并让用户自行决定。
- [ ] **分析结果操作化**：为重复文件 / 大文件提供受控的后续操作（如打开位置已支持；清理或移动必须重新设计为明确 Review 流程，不能直接复用 Safe 清理）。
- [ ] **下载目录整理**：安装包、压缩包等按扩展名与时间筛选；由于可能包含用户资料，必须为 Review 级且默认不勾选。
- [ ] **浏览器配置清理**：Cookie、历史、密码等不属于垃圾清理范围，v1 明确不做；若未来提供，必须完全独立于缓存规则并强确认。

## 3. 扫描引擎（P1）

- [ ] **流式结果**：当前扫描结束后一次性返回全部条目。需要分批回传、增量聚合与可取消的分页预览。
- [ ] **移除 100,000 条固定上限**：改为可配置上限 + 分页持久化 + 磁盘占用保护；UI 必须能处理百万级条目而不卡顿。
- [ ] **按类别扫描**：允许用户只扫描选中的规则类别（当前固定扫描所有 Safe 规则）。
- [ ] **排除正在使用 / 受保护目录**：结合排除列表与进程检测，减少无效 IO。
- [ ] **扫描结果持久化与复用**：应用重启后可查看上次结果，需定义过期与失效策略。
- [ ] **并行 / 低优先级扫描**：评估多 isolate 并行与 Windows IO 优先级；避免影响前台应用。
- [ ] **NTFS 快速索引**：评估 USN Journal / MFT 读取，需管理员权限与 NTFS 限定，作为可选加速路径，不替代逐目录回退。
- [ ] **更细的错误上报**：按目录汇总无权限、路径过长、设备不可用等错误，而不仅是计数。
- [ ] **扫描规则更新**：规则从应用内置迁移到可更新数据（需签名 / 校验与回滚），或至少支持应用版本升级时合并用户排除项。
- [ ] **路径语义抽象**：核心代码大量直接使用 `p.windows`。跨平台前需要抽象路径规范化、大小写敏感性、根路径、移动语义与保留名规则。

## 4. 预览与选择（P1）

- [ ] **单文件选择**：当前只能按规则勾选。需要虚拟化列表中的多选、全选、反选与跨规则汇总。
- [ ] **搜索与排序**：按路径、扩展名、大小、修改时间筛选排序。
- [ ] **在资源管理器中显示**：提供“打开所在文件夹”，只读操作，注意路径失效。
- [ ] **规则详情增强**：展示规则来源、风险、路径模板、解析后的实际根目录、过滤条件与清理后果。
- [ ] **扫描摘要**：显示各分类体积占比、可清理总量、被跳过数量与截断提示。
- [ ] **无障碍与键盘操作**：完整焦点顺序、快捷键（扫描 / 取消 / 返回）与语义标签。
- [ ] **国际化**：UI 文案目前硬编码中文，且未配置 `flutter_localizations`。需要 ARB 体系、语言切换与日期 / 数字本地化。
- [ ] **主题设置**：目前仅跟随系统；增加明亮 / 深色 / 跟随系统的手动选项与持久化。
- [ ] **首次使用引导**：解释“隔离区”“Safe 级”和安全边界。

## 5. 隔离区与撤销（P0 / P1）

- [x] **独立隔离区管理页**：浏览会话、条目、总大小、状态与剩余待恢复项。
- [x] **撤销范围选择**：支持整会话恢复或按条目恢复。
- [x] **永久删除**：独立于撤销，二次确认、逐会话或整体释放；默认入口弱化，并明确不可恢复与“释放后才回收磁盘空间”。
- [ ] **隔离区迁移与加密**：支持用户更改隔离区位置；如需加密需评估密钥管理与性能，不作为近期目标。
- [ ] **磁盘空间预检**：清理前检查隔离区剩余空间，跨卷复制回退时尤其重要；空间不足应中止而不是产生半完成文件。
- [ ] **恢复顺序与冲突可见性**：逐项展示冲突原因，允许跳过并继续，不因单项失败中断整批。
- [ ] **会话格式版本化**：`schemaVersion` 已存在，需要迁移器与向后兼容测试；未知版本必须拒绝处理而不是猜测。
- [ ] **清理历史**：当前完成报告与待撤销会话是两套概念。需要持久化历史记录（时间、规则、数量、体积、结果），与隔离区生命周期解耦。

## 6. 调度与自动化（P2）

- [ ] **定时扫描 / 清理**：仅允许 Safe 级、默认只扫描不自动清理；自动清理必须显式开启并设置保留期。
- [ ] **托盘与后台运行**：最小化到托盘、通知、退出行为。
- [ ] **开机启动**：可选项，默认关闭。
- [ ] **CLI / 无头模式**：`broom scan --json`、`broom clean --rules ...`，明确退出码、dry-run 与供自动化调用的稳定输出格式。
- [ ] **报表导出**：JSON / CSV 清理报告，注意路径隐私。
- [ ] **系统空闲检测**：低优先级扫描或后台任务的前置条件。

## 7. 设置与配置（P1）

- [ ] **设置页**：规则开关、排除列表、隔离区位置与保留策略、主题、语言、定时任务。
- [ ] **配置持久化**：选择一个跨版本稳定的存储位置（建议 `%APPDATA%\Broom` 或 `%LOCALAPPDATA%\Broom`），带 schema 版本与迁移。
- [ ] **重置与导入导出**：恢复默认设置、导出配置（不含隔离区文件）。
- [ ] **隐私开关**：v1 无遥测、无联网。若未来增加崩溃上报或匿名统计，必须默认关闭、明确告知并可撤回。

## 8. 工程与质量（P1）

- [ ] **Widget / 集成测试补全**：预览选择、清理确认、进度、撤销成功 / 冲突流程、部分会话恢复、错误提示。
- [ ] **文件系统测试替身**：引入可注入文件系统，避免测试依赖真实临时目录与平台时序。
- [ ] **恶意 / 损坏元数据测试**：非法会话 ID、路径穿越、超长 storedName、未知状态、截断 JSONL。
- [ ] **并发测试**：清理、撤销、扫描同时触发的状态机保护；当前控制器用 phase 拦截，但需要系统化验证。
- [ ] **性能基准**：10 万 / 100 万文件扫描、内存峰值、isolate 传输成本、UI 帧率。
- [ ] **Windows CI**：`flutter analyze`、`flutter test`、构建与产物上传；当前仅有本地验证。
- [ ] **日志与诊断**：本地滚动日志（不含文件内容），支持导出用于问题排查；必须默认关闭或最小化。
- [ ] **静态检查收口**：启用更严格 lint、`dart format` 校验、未使用代码检查。
- [ ] **崩溃与错误上报**：若加入，遵循隐私开关与最小化字段；不记录用户路径明文，除非用户主动导出。

## 10. 平台扩展（P2）

### macOS

- [ ] 规则根：`~/Library/Caches`、应用容器缓存、部分 `~/Library/Application Support/<app>/Cache`；必须逐应用验证，不做整目录猜测。
- [ ] 权限：App Sandbox 与 Full Disk Access 的取舍；未授权路径必须安全跳过。
- [ ] 撤销：仍使用应用自管隔离区；若接入废纸篓，需要处理与 Finder 的交互。

### Linux

- [ ] 规则根：`$XDG_CACHE_HOME`（默认 `~/.cache`）及常见开发工具缓存。
- [ ] 路径与权限：大小写敏感、符号链接、Flatpak / Snap 沙箱隔离。
- [ ] 打包：AppImage / deb / snap 的隔离区与配置目录规范。

### 移动端

移动端目前只保留 `CleanerPlatform` 接口，显示不支持页面。真正接入前必须先完成“路径语义抽象 + 文件系统后端”重构，不能直接复用 Windows 扫描器。

- [ ] **Android**：
  - [ ] 访问自身缓存与用户通过 SAF（`ACTION_OPEN_DOCUMENT_TREE`）授权的目录。
  - [ ] 使用 MediaStore 处理媒体文件时遵守分区存储与“废纸篓 / 待删除”机制。
  - [ ] 无法枚举其他应用私有缓存是平台限制，不通过 root / 漏洞绕过；可在系统中引导用户前往系统存储设置。
  - [ ] 后台扫描受电池与前台服务限制，需要明确任务调度策略。
- [ ] **iOS**：
  - [ ] 仅应用沙箱内可管理内容；系统级“清理”不可实现，应定位为自身缓存管理。
  - [ ] 接入系统存储管理提示与文件 App 授权目录的只读 / 可写边界。
- [ ] **移动端撤销**：SAF 文档移动不等于重命名；需设计“复制 + 删除”或平台回收站语义，失败时保证原文件不变。
- [ ] **UI 适配**：桌面信息密度与触控布局分离，规则明细改为移动端列表。

## 建议里程碑

不承诺日期，仅给出依赖顺序：

1. **v1.1 安全与可管理性**：设置页、国际化、单文件选择。（排除列表、撤销冲突处理与隔离区保留/容量策略已完成；隔离区管理页、按范围恢复与永久释放已在 v4 完成）

## 非目标

以下内容不在 Broom 的产品方向内，或需要重新论证后才考虑：

- 注册表清理、驱动更新、内存 / RAM 加速、系统“优化”评分。
- 杀毒、反恶意软件或安全扫描。
- 通过启发式猜测删除“看起来没用”的个人文件。
- 强制删除、绕过文件锁、绕过系统权限或使用 root / 漏洞访问其他应用私有数据。
- 清理系统还原点、Windows.old、Windows Update 历史等不可逆或影响系统回滚的操作（即使未来提供管理员模式，也需单独设计）。
- 删除浏览器密码、Cookie、历史等隐私数据；v1 浏览器规则严格限定缓存。
- 自动清理用户下载目录中的“疑似垃圾”；此类内容只能作为可审阅的分析结果。
- 云端文件内容扫描；Broom 保持离线，不上传用户文件名或路径。
