# 文件占用检测与跳过 / 失败分类

Broom 在清理预览阶段提示**可能被占用**的文件，并在清理结果中把“跳过”与“失败”分开统计。占用检测是只读的：不写入文件、不关闭进程、不强制解锁。

## 行为约定

- **只读探测**：原生通道尝试以 `DELETE` 访问打开目标文件，但允许其他进程读写与删除（`FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE`），随后立即关闭句柄。只有调用进程本身获得删除权限，才能说明随后的移动 / 删除大概率不会被共享冲突阻止。
- **可能而非确定**：探测与真正清理之间存在时间差（TOCTOU），其他程序可能在此期间打开或关闭文件。因此界面使用“可能被占用”措辞，实际结果以清理时的文件操作返回值为准。
- **不强制解锁**：被占用的文件会保留在原处，等待用户关闭相关程序后重试；Broom 不会结束进程、调整共享模式或绕过锁。
- **不阻塞预览**：扫描完成、进入预览后才在后台分批探测，每批 512 个文件。探测进度显示为“正在检测被占用的文件…（已检查 / 总数）”；失败、超时或当前系统不支持时静默降级，预览、勾选与清理仍然可用。
- **不改变选择**：占用状态只是提示。被标记的文件仍可勾选，默认选择规则保持不变；操作栏会额外提示已选文件中有多少可能被占用。
- **清理前停止探测**：开始清理、重新扫描、返回首页或销毁控制器时递增探测代次，丢弃未完成的结果，避免探测句柄与清理操作互相干扰。

## 原生实现

| 部分 | 说明 |
| --- | --- |
| 平台通道 | `broom/file_lock`，方法 `probe`，参数 `{ 'paths': List<String> }`，返回与输入等长的 `List<bool>` |
| 探测调用 | `CreateFileW(path, DELETE, FILE_SHARE_READ \| FILE_SHARE_WRITE \| FILE_SHARE_DELETE, nullptr, OPEN_EXISTING, FILE_FLAG_BACKUP_SEMANTICS, nullptr)` |
| 占用判定 | 打开失败且错误码为 `ERROR_SHARING_VIOLATION (32)` 或 `ERROR_LOCK_VIOLATION (33)` |
| 长路径 | 复用 `ToExtendedWindowsPath`，本地路径补 `\\?\`，UNC 补 `\\?\UNC\` |
| Linux 探测 | 解析 `/proc/locks`，用 `lstat` 的 `st_dev` / `st_ino` 匹配 **写** 类型的 POSIX / OFD / flock 锁；只读共享不报告 |
| 其他平台 | 使用 `NoopFileLockProbe`，不报告占用 |
| 异常 | 结果缺失或通道不可用时抛出 `FileLockProbeException`，控制器捕获后保持预览可用 |

Dart 侧的 `runLockProbe` 负责分批、取消与进度回调；两个控制器（Safe 清理与系统缓存）共用同一实现，只在规则维度上分别统计占用数量。

## 跳过与失败

清理报告（`CleanReport` 与 `SystemCleanReport`）新增 `skippedCount` 与 `skips`，与 `failureCount` / `failures` 并列。详情最多保留 100 条，计数始终完整。

| 场景 | 分类 | 处理 |
| --- | --- | --- |
| 文件被其他进程占用（共享 / 锁冲突，32 / 33） | 跳过 | 保留原文件，可稍后重试 |
| 扫描后文件消失或不再是普通文件 | 跳过 | 不做任何更改 |
| 符号链接 / junction | 跳过 | 不跟随、不删除目标 |
| 位于排除列表 | 跳过 | 尊重用户排除项 |
| 路径守卫拒绝、根目录不可信 | 失败 | 需要检查规则或路径 |
| 权限不足、磁盘 / 网络 / 文件系统 IO 错误 | 失败 | 显示原始错误提示 |
| 撤销记录写入失败、清理计划损坏 | 失败 | 为保证可撤销性而停止该项 |

隔离区清理在移动失败且确认隔离目录中没有对应文件时，会截断刚写入的撤销记录，避免留下指向不存在文件的“幽灵条目”；存在部分复制内容的条目会保留，供后续检查或释放。

## 界面呈现

- **预览页**：检测期间显示进度横幅；完成后显示“有 N 个文件可能正被其他程序占用”，规则卡片显示该规则的占用数量。Safe 规则详情逐项显示锁图标与提示。
- **操作栏**：已选文件包含占用项时提示“已选文件中有 N 个可能被占用，清理时会跳过”。
- **完成页**：跳过与失败使用独立面板。跳过面板说明这些文件仍保留在原位置，通常是被占用或已不存在；失败面板说明权限、路径或磁盘错误。两者都有时不合并计数。
- **系统缓存**：复用相同探测与分类；不同的只是清理方式为永久删除，并且会先停止相关服务。
- **断点续跑**：继续清理的摘要同时显示已跳过数量，跳过项不会阻止会话完成。

## 已知限制

- Linux 只检测 advisory 写锁；程序单纯打开文件读写、未加锁时不会提示。Windows 仍以共享 / 删除冲突为主。
- 探测只检查占用信号，不模拟跨卷“复制 + 删除”中的读取阶段；网络盘上的瞬时错误可能在清理时才暴露。
- 杀毒软件、索引服务或短暂扫描可能造成一次性误报或漏报。
- 被标记为占用不会阻止用户勾选；如果用户坚持清理，结果仍以实际跳过 / 失败为准，不会尝试解锁。
